# 版本与发布策略

InkTag 固件、OTA 包、Web 上位机和用户文档使用统一的语义版本号 `主版本.次版本.修订号`。

- `0.x.y`：功能和协议仍可能变化的预览版本。
- `1.x.y`：完成支持矩阵回归并承诺兼容策略后的稳定版本。
- 正式版标签使用 `v<版本>`；预发布使用独立 SemVer 标签，例如
  `v0.2.0-preview.1`。每个标签只对应一个 GitHub Release。

发布仓库的 `main` 始终指向最新一次发布快照。历史版本通过不可变标签和 GitHub
Release 保留，不在 `main` 下累积多个版本目录。一次发布可以只包含 CLI、WebUI 或
筛选后的固件；实际内容以 `firmware/manifest.json` 为准。

发布遵循“构建一次、测试同一份字节、再原样提升”的原则。实机测试完成后不得重新编译再发布；所有发布文件必须记录大小和 SHA-256。

状态含义：

- **测试版**：主要流程已经过实机测试，但仍有明确的发布门槛。
- **实验性**：可以构建或部分运行，尚未完成完整实机验证。
- **规划中**：仅保留路线图信息，不发布固件。

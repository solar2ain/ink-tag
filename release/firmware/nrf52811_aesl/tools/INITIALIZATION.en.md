# nRF52811 initialization and preservation flashing

These entries use Windows PowerShell 5.1, Windows .NET Framework and the existing J-Link backend. **They neither require nor bundle Python, InkTag CLI, BLE or Find services.** Offline generation needs no device or J-Link installation. Programming requires SEGGER J-Link 7.88j, its USB driver and SWD wiring. Obtain the vendor software under SEGGER's terms; no vendor DLL or private SDK is included.

The supplied configurations target EL022HWRL / CAL_VER06 with an actual nRF52811, 192 KiB Flash / 24 KiB RAM and the supported 512 KiB external Flash. Select the supplied original-panel or supported replacement-panel configuration. An MCU match alone does not qualify another board.

Double-click `flash.bat` for English or `flash-zh.bat` for Chinese; the launcher also works from another current directory. The opening guide explains J-Link 7.88j, SWDIO / SWCLK / GND wiring, target power, initialization scope and cancellation. A single validated Full ZIP beside the tools or in a neighboring `firmware` or `full` directory is selected automatically; multiple valid files produce a selection menu. If none is available, a Windows file dialog opens. OTA archives and standalone Apps are not accepted as Full images. Only after firmware validation does the menu offer the supplied board-marking/panel configurations from `native-configs`.

After firmware and board validation, the tool explains the complete-flashing scope and asks whether to proceed, defaulting to No. Answering No or leaving it blank exits without probe enumeration, port or target access. Only after consent does it poll indefinitely for a USB probe and powered SWD target, display waiting status and accept Q or Esc to cancel. Target chip, capacity and all existing write checks still run before programming. Empty menu input cancels; an invalid number, missing dependency, validation error or programming failure remains visible until a key is pressed. Complete flashing resets ordinary settings and invalidates old image slots. Only pre-write discovery retries; failed writes are never replayed automatically.

CMD calls with parameters retain their existing behavior. Supplied inputs skip their prompts. BAT calls with parameters, including `-Yes` automation and `-DryRun`, never pause on exit. Provide complete paths with `-Yes`; that path fails immediately when a probe or target is missing. One J-Link is selected automatically; multiple probes require `-Snr` with a serial listed by the existing backend. `generate-hex.bat` asks for configuration, Full and a new output directory; `flash-hex.bat` asks for an existing materials directory.

The normal, recommended complete-flashing entry is `flash.bat`. It first attempts to preserve usable original information and uses defaults when it is absent. Complete flashing resets ordinary settings and invalidates old image slots; see the preservation scope below.

```bat
flash.bat -Firmware "D:\Firmware\app-full.zip" -Config ".\native-configs\EL022HWRL.toml" -Yes
```

To generate reusable HEX materials offline first, use these two entries:

```bat
generate-hex.bat -Firmware "D:\Firmware\app-full.zip" -Config ".\native-configs\EL022HWRL.toml" -Output "D:\Firmware\new initialization"
flash-hex.bat -Materials "D:\Firmware\new initialization" -Yes
```

`-Firmware` selects an external Full ZIP with matching App, Recovery, SoftDevice / MBR and GUI. An OTA ZIP or App.bin is insufficient. Tools do not contain or download firmware. Use `-Help` for parameters or `-DryRun` to validate without opening a probe. Select a probe with `-Snr SERIAL`, or a vendor installation with `-JLinkExe "C:\...\JLink.exe"`.

## Generated materials

| File | Address space | Start | Decoded bytes |
| --- | --- | --- | --- |
| `internal.hex` | MCU internal Flash | `0x00000000` | 196608 B |
| `settings.hex` | External SPI Flash | `0x00000000` | 8192 B |
| `gui-assets.hex` | External SPI Flash | `0x00002000` | 12288 B |

`addresses.json` binds addresses, ranges and file SHA-256 values. `source-full.zip` and `board.toml` retain the generation inputs; the BAT validates them and compares regenerated bytes before programming. Keep the whole materials directory together.

The internal image contains MBR / S112, App, Recovery and fresh SDK boot settings. External defaults contain board routing, panel configuration and the first-display record. Generic materials contain no previous device UID, MAC, device QR, label, password, health or activation data. The existing Nordic SoftDevice reads its lifetime manufactured FICR address at boot; App and Recovery retain the same address. Generation needs no device read and never inserts a test MAC. Import a device QR and label later through the existing WebUI settings.

Internal and external Flash are separate address spaces. Programming only `internal.hex` is incomplete. Use the BAT when a window programmer cannot access this board's external SPI Flash. Do not request chip Recover / Unlock or overwrite FICR / UICR.

## Initialization and preservation scope

Both programming modes reset ordinary settings, previous QR / labels, health, crash and reset records, and invalidate previous image indices. The existing exception invalidates four-byte image heads; it **does not securely erase image pixels**. No automatic user-data backup is made.

`flash.bat` first attempts to read the original UID, address and UICR. Blank, damaged or unavailable optional old data is reported individually and uses normal initialization. Writes skip FICR, UICR and external `0x5000..0x9FFF`. Another device's manufacturing data is never inserted in generic materials. This independent nRF52811 target is Base-only and does not read, copy or create Pro activation records.

Wrong chip or physical capacity, connection failure, supply outside the existing J-Link 2.7–3.6 V range, an unknown write result or readback mismatch fails the operation. No failed write is automatically replayed and no extra reset hides failure. Only after independent internal, external settings / GUI and image-head readback matches does the tool clear volatile state and perform one final reset. Logs distinguish generation, confirmed programming and matched readback; these do not constitute App functional or optical qualification.

Use `-Output` for a new evidence directory. J-Link 7.88j requires a short ASCII evidence path; spaces are supported. Existing output directories are not overwritten.

Developer `make full` / `build.ps1` still use Python, WSL and the Nordic / Arm build toolchain. Those build dependencies are separate from these user programmer entries.
